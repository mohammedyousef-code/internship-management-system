🔑 Points Importants

• Toutes les routes admin nécessitent l'authentification (auth:sanctum) et le rôle admin

• Chaque CRUD utilise des FormRequests pour la validation

• Les réponses sont standardisées avec success, message, et data

• Les transactions DB sont utilisées pour les opérations complexes

⚡ Opération Spéciale: Changer le Statut

PATCH/api/admin/offres/{id}/status public function updateStatus(Request $request, $id) { $request->validate([ 'statut' => 'required|in:ouvert,ferme' ]); $offre = Offre::findOrFail($id); $offre->update(['statut' => $request->statut]); return response()->json(['success' => true]); }

✅ Opération Complexe: ACCEPTER une Candidature

PATCH/api/admin/candidatures/{id}/accept

// Processus complet avec transaction public function accept(AcceptCandidatureRequest $request, $id) { DB::beginTransaction(); $candidature = Candidature::with(['stagiaire.user', 'offre']) ->findOrFail($id); // 1. Vérifier statut if ($candidature->statut !== 'en_attente') { return error('Déjà traitée'); } // 2. Vérifier pas de stage en cours $hasActiveStage = Stage::whereHas('candidature', function($q) { $q->where('stagiaire_id', $candidature->stagiaire_id); })->where('statut', 'en_cours')->exists(); if ($hasActiveStage) { return error('Stage déjà en cours'); } // 3. Mettre à jour candidature $candidature->update([ 'statut' => 'accepte', 'date_reponse' => now() ]); // 4. Créer le stage $stage = Stage::create([ 'candidature_id' => $candidature->id, 'encadrant_id' => $request->encadrant_id, 'statut' => 'en_cours' ]); // 5. Notifications NotificationService::candidatureAcceptee($candidature->stagiaire, $candidature->offre); NotificationService::nouveauStagiaire($encadrant, $candidature->stagiaire); // 6. Emails Mail::to($candidature->stagiaire->user->email) ->send(new CandidatureAcceptee($candidature, $stage)); DB::commit(); return response()->json(['success' => true]); }

❌ Opération: REFUSER une Candidature

public function reject($id) { DB::beginTransaction(); $candidature = Candidature::with(['stagiaire.user', 'offre'])->findOrFail($id); $candidature->update([ 'statut' => 'refuse', 'date_reponse' => now() ]); // Notification et email NotificationService::create(...); Mail::to($candidature->stagiaire->user->email) ->send(new CandidatureRefusee($candidature)); DB::commit(); return response()->json(['success' => true]); }

// Créer User + Encadrant public function store(StoreEncadrantRequest $request) { DB::beginTransaction(); // Générer mot de passe temporaire $tempPassword = Str::random(12); // Créer l'utilisateur $user = User::create([ 'name' => $request->name, 'email' => $request->email, 'password' => Hash::make($tempPassword), 'role' => 'encadrant' ]); // Créer le profil encadrant $encadrant = Encadrant::create([ 'user_id' => $user->id, 'departement_id' => $request->departement_id, 'specialite' => $request->specialite ]); // Envoyer email avec identifiants Mail::to($user->email) ->send(new WelcomeEncadrant($user, $tempPassword)); DB::commit(); return response()->json(['success' => true], 201); }

📌 Récapitulatif des Patterns CRUD

🎯 Patterns Communs

1. Structure de Réponse Standardisée:

{ "success": true, "message": "Message descriptif", "data": { ... }, "pagination": { ... } // si applicable }

2. Vérifications Avant Suppression:

  • Offres → Vérifier candidatures existantes
  • Encadrants → Vérifier stages en cours
  • Stagiaires → Vérifier stage en cours
  • Départements → Vérifier encadrants et offres

3. Transactions DB:

Utilisées pour les opérations qui modifient plusieurs tables (Encadrants, Candidatures)

4. Relations Eager Loading:

Toujours charger les relations avec with() pour éviter le problème N+1

5. Filtrage et Recherche:

Tous les INDEX supportent des filtres via query parameters

🌐 Les Méthodes HTTP (CRUD)
📖 GET
Action: Récupérer des données
Utilisation: Lire des ressources sans modification
GET /api/admin/offres
→ Récupère toutes les offres
➕ POST
Action: Créer une nouvelle ressource
Utilisation: Ajouter de nouvelles données
POST /api/admin/offres
→ Crée une nouvelle offre
✏️ PUT
Action: Modifier complètement une ressource
Utilisation: Remplacer toutes les données
PUT /api/admin/offres/5
→ Modifie l'offre #5
🔧 PATCH
Action: Modifier partiellement une ressource
Utilisation: Mettre à jour certains champs
PATCH /api/admin/offres/5/status
→ Change le statut de l'offre #5
🗑️ DELETE
Action: Supprimer une ressource
Utilisation: Effacer des données
DELETE /api/admin/offres/5
→ Supprime l'offre #5
💡 Exemple Complet: CRUD des Offres

1 INDEX - Lister toutes les offres

// Route GET /api/admin/offres // Controller: OffreController@index public function index(Request $request) { $query = Offre::with(['departement', 'createur']); // Filtres if ($request->has('statut')) { $query->where('statut', $request->statut); } $offres = $query->paginate(15); return response()->json([ 'success' => true, 'offres' => OffreResource::collection($offres) ]); }

2 STORE - Créer une nouvelle offre

// Route POST /api/admin/offres // Body JSON { "titre": "Stage Développement Web", "description": "Stage de 2 mois...", "departement_id": 1, "duree_jours": 60 } // Controller: OffreController@store public function store(StoreOffreRequest $request) { $offre = Offre::create([ 'titre' => $request->titre, 'description' => $request->description, 'departement_id' => $request->departement_id, 'created_by' => auth()->id() ]); return response()->json([ 'success' => true, 'message' => 'Offre créée avec succès', 'offre' => new OffreResource($offre) ], 201); }

3 SHOW - Afficher une offre spécifique

// Route GET /api/admin/offres/5 // Controller: OffreController@show public function show($id) { $offre = Offre::with(['departement', 'createur', 'candidatures']) ->findOrFail($id); return response()->json([ 'success' => true, 'offre' => new OffreResource($offre) ]); }

4 UPDATE - Modifier une offre

// Route PUT /api/admin/offres/5 // Body JSON { "titre": "Stage Dev Web - Modifié", "duree_jours": 90 } // Controller: OffreController@update public function update(UpdateOffreRequest $request, $id) { $offre = Offre::findOrFail($id); $offre->update($request->validated()); return response()->json([ 'success' => true, 'message' => 'Offre modifiée avec succès', 'offre' => new OffreResource($offre) ]); }

5 DESTROY - Supprimer une offre

// Route DELETE /api/admin/offres/5 // Controller: OffreController@destroy public function destroy($id) { $offre = Offre::findOrFail($id); // Vérification avant suppression if ($offre->candidatures()->exists()) { return response()->json([ 'success' => false, 'message' => 'Impossible de supprimer' ], 422); } $offre->delete(); return response()->json([ 'success' => true, 'message' => 'Offre supprimée' ]); }
🏗️ Architecture en Couches

1️⃣ ROUTES (routes/api.php)

• Définit les endpoints de l'API

• Associe les URLs aux contrôleurs

• Applique les middlewares (auth, roles)

Route::middleware('admin')->prefix('admin')->group(function () { Route::get('/offres', [OffreController::class, 'index']); Route::post('/offres', [OffreController::class, 'store']); });

2️⃣ MIDDLEWARE (app/Http/Middleware)

• auth:sanctum - Vérifie l'authentification

• admin - Vérifie le rôle administrateur

• stagiaire - Vérifie le rôle stagiaire

• encadrant - Vérifie le rôle encadrant

3️⃣ CONTROLLERS (app/Http/Controllers)

• Reçoit la requête du middleware

• Valide les données (FormRequest)

• Appelle le Model pour manipuler les données

• Formate la réponse (Resource)

• Gère la logique métier

4️⃣ SERVICES (app/Services)

• NotificationService - Gestion des notifications

• AttestationService - Génération PDF

• RapportService - Gestion des rapports

• Logique métier réutilisable

5️⃣ MODELS (app/Models)

• Représente les tables de la base de données

• Définit les relations (hasMany, belongsTo)

• Utilise Eloquent ORM

class Offre extends Model { public function candidatures() { return $this->hasMany(Candidature::class); } }

6️⃣ DATABASE (MySQL)

• Stocke les données persistantes

• Tables: offres, candidatures, stages, users, etc.

• Relations via clés étrangères

🎯 Exemple de Flow Complet: Accepter une Candidature

🔔 Processus Complexe avec Notifications et Emails

Cet exemple montre comment plusieurs composants travaillent ensemble.

Étape par Étape

// 1. CLIENT envoie la requête PATCH /api/admin/candidatures/10/accept Headers: Authorization: Bearer {token} Body: { "encadrant_id": 5 } // ↓↓↓ ROUTE (api.php) ↓↓↓ Route::middleware(['auth:sanctum', 'admin']) ->patch('/candidatures/{id}/accept', [CandidatureController::class, 'accept']); // ↓↓↓ MIDDLEWARE auth:sanctum ↓↓↓ Vérifie le token → User authentifié ✓ // ↓↓↓ MIDDLEWARE admin ↓↓↓ Vérifie role === 'admin' → Autorisé ✓ // ↓↓↓ CONTROLLER CandidatureController@accept ↓↓↓ public function accept(AcceptCandidatureRequest $request, $id) { DB::beginTransaction(); // 1. Récupérer la candidature $candidature = Candidature::with(['stagiaire.user', 'offre']) ->findOrFail($id); // 2. Vérifications métier if ($candidature->statut !== 'en_attente') { return error('Déjà traitée'); } // 3. Mettre à jour la candidature $candidature->update([ 'statut' => 'accepte', 'date_reponse' => now() ]); // 4. Créer le stage $stage = Stage::create([ 'candidature_id' => $candidature->id, 'encadrant_id' => $request->encadrant_id, 'statut' => 'en_cours' ]); // 5. Envoyer notification au stagiaire NotificationService::candidatureAcceptee( $candidature->stagiaire, $candidature->offre ); // 6. Envoyer email au stagiaire Mail::to($candidature->stagiaire->user->email) ->send(new CandidatureAcceptee($candidature)); DB::commit(); return response()->json([ 'success' => true, 'message' => 'Candidature acceptée', 'candidature' => new CandidatureResource($candidature) ]); } // ↓↓↓ RÉPONSE au CLIENT ↓↓↓ { "success": true, "message": "Candidature acceptée avec succès", "candidature": { ... } }

🔑 Points Clés à Retenir

🔒 Sécurité

• Toutes les routes protégées utilisent auth:sanctum

• Les middlewares vérifient les rôles

• Validation des données avec FormRequest

📦 Organisation

• Controllers séparés par rôle (Admin/, Stagiaire/, Encadrant/)

• Services pour logique réutilisable

• Resources pour formater les réponses

💾 Base de Données

• Eloquent ORM pour les queries

• Relations entre modèles

• Transactions pour intégrité

📧 Notifications

• NotificationService pour BDD

• Mailables pour emails

• Notifications en temps réel

🎓 Résumé

Le backend Laravel utilise une architecture MVC avec des routes RESTful, des middlewares pour la sécurité, des controllers pour la logique, des models Eloquent pour la base de données, et des services pour la logique métier réutilisable. Chaque requête passe par plusieurs couches qui garantissent la sécurité, la validation et la cohérence des données.
